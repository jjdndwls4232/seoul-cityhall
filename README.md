# 서울특별시청 홈페이지 리뉴얼

> HTML, CSS, JavaScript(jQuery)로 만든 서울특별시청 메인 페이지 퍼블리싱 프로젝트입니다.
> 많은 정보 속에서도 시민이 원하는 서비스를 빠르게 찾을 수 있는 화면을 목표로 했습니다.

그래서 이 프로젝트에서는 화려한 효과보다 **정보를 묶고, 순서대로 보여주고, 누구나 조작할 수 있게** 만드는 데 집중했습니다.

<br>

## 주요 기능

### 1. 상단 배너 "오늘 하루 보지 않기"

- `localStorage`에 오늘 날짜를 저장해서, 같은 날에는 배너가 다시 나타나지 않게 했습니다.
- 일반 닫기는 저장하지 않아서 새로고침하면 다시 보입니다.

### 2. 전체 메뉴 모달

- 메뉴 버튼을 누르면 전체 메뉴가 화면 위에 열립니다.
- 모달이 열린 동안 뒤쪽 페이지의 스크롤을 잠그고, 어두운 배경을 클릭해도 닫히게 했습니다.
- 열림과 닫힘 상태를 `aria-expanded`로 스크린 리더에 전달합니다.

### 3. 자주 찾는 서비스 탭

- 탭을 누르면 해당 분류의 서비스 아이콘만 보여줍니다.
- 아이콘은 한 번에 8개씩 보여주고, 이전/더보기 버튼으로 넘길 때 방향에 맞는 애니메이션이 적용됩니다.

### 4. 시정홍보 슬라이드

- 탭(주요 소식 / 시민 안내)마다 이미지를 따로 관리하고, 각 탭의 현재 위치를 기억합니다.
- 5초마다 자동으로 넘어가며 재생/일시정지 버튼으로 제어할 수 있습니다.
- 마지막 이미지에서 다음을 누르면 처음으로 돌아가는 순환 구조입니다.
- 목록 버튼을 누르면 전체 이미지를 모달로 보여주고, 원하는 이미지를 바로 선택할 수 있습니다.

### 5. 서울 소식 카드 슬라이더

- 카테고리 탭을 누르면 해당 카드 6개만 보여주고 첫 카드 위치로 돌아갑니다.
- 좌우 버튼으로 카드 한 장씩 이동하며, 처음과 마지막 위치에서는 버튼이 비활성화됩니다.
- 화면 크기가 바뀌면 카드 너비와 버튼 상태를 다시 계산합니다.

### 6. 날씨 · 미세먼지 위젯

- OpenWeatherMap API로 서울의 현재 기온과 날씨 아이콘을 보여줍니다.
- 미세먼지(PM10)와 초미세먼지(PM2.5)는 환경부 기준으로 좋음/보통/나쁨/매우 나쁨 등급을 표시합니다.
- 불러오는 중, 실패 상태를 따로 보여주고, 실패하면 "다시 시도" 버튼을 제공합니다.

## 신경 쓴 부분

### 웹 표준과 시맨틱 마크업

- `header`, `nav`, `main`, `section`, `article`, `footer`로 문서 구조를 나눴습니다.
- 메뉴 영역은 역할에 따라 `nav`를 나누고 `aria-label`(주 메뉴, 유틸리티 메뉴, 소식 카테고리)로 구분했습니다.

### 웹 접근성

- 아이콘만 있는 버튼(이전, 다음, 재생, 목록, 닫기)에 `aria-label`을 넣어 스크린 리더에서도 기능을 알 수 있게 했습니다.
- 선택된 탭은 `aria-current`, `aria-selected`로 현재 상태를 전달합니다.
- 슬라이드와 모달 이미지는 "탭 이름 + 몇 번째 이미지" 형식의 대체 텍스트를 자동으로 생성합니다.

### 유지보수를 고려한 구조

- CSS는 역할에 따라 `reset` / `font` / `common` / `main` / `media`로 나눴습니다.
- JS는 기능 단위로 파일을 분리했습니다.

## 트러블슈팅

### 1. 슬라이드 버튼을 빠르게 연타하면 위치가 어긋나는 문제

- **문제:** 애니메이션이 끝나기 전에 버튼을 여러 번 누르면 이동 거리가 겹쳐서 카드가 어중간한 위치에 멈췄습니다.
- **해결:** `isMoving` 상태값을 두고, 애니메이션이 진행되는 동안에는 클릭을 무시하도록 했습니다.

### 2. 마지막 카드에서 오른쪽 버튼이 비활성화되지 않는 문제

- **문제:** 브라우저가 스크롤 위치를 소수점으로 계산해서, 끝까지 이동해도 최대값과 정확히 같아지지 않았습니다.
- **해결:** 최대 이동 거리에서 1px 여유를 두고 비교하도록(`currentScroll >= maxScroll - 1`) 수정했습니다.

### 3. 슬라이드 이미지가 계속 쌓이는 문제

- **문제:** 이미지를 넘길 때마다 새 `img`가 추가되기만 해서 요소가 계속 늘어났습니다.
- **해결:** 퇴장 애니메이션이 끝난 뒤 이전 이미지를 제거해서 항상 하나만 남도록 했습니다.

### 4. 날씨 아이콘 조건문이 너무 길어지는 문제

- **문제:** `switch`문으로 날씨마다 이미지 코드를 반복해서 작성하니 코드가 길고 수정하기 어려웠습니다.
- **해결:** 날씨 코드와 이미지, 설명을 객체로 묶어 데이터로 분리했습니다. 이제 날씨 종류를 추가할 때 객체 한 곳만 수정하면 됩니다.

## 배운 점

- 정보가 많은 사이트일수록 **디자인보다 정보 구조를 먼저 정리해야** 한다는 것을 배웠습니다.
- 슬라이드, 탭 같은 UI도 연타, 화면 크기 변경, 첫 위치와 마지막 위치처럼 **예외 상황까지 처리해야** 완성이라는 것을 알게 됐습니다.
- 접근성 속성은 눈에 보이지 않지만, 누구나 쓸 수 있는 화면을 만들려면 꼭 필요하다는 것을 직접 적용하며 익혔습니다.

<br>

## 앞으로 개선할 점

- 태블릿 구간(768px ~ 1023px)을 따로 나눠 더 세밀한 반응형 적용
- 키보드만으로 모달을 조작할 수 있도록 포커스 이동과 ESC 닫기 추가
- API 키를 프론트엔드 코드에서 분리 (서버를 거쳐 호출하는 방식)
